# AI 모델/프롬프트 변경 사전 검토 프로세스

앱인토스 정책 요건: **"AI 모델이나 프롬프트를 변경할 경우, 앱 배포 검토를 사전에 요청해 주세요."**
이 문서는 그 요건을 만족하기 위한 최소 프로세스를 정의한다. 대상은 미니앱뿐 아니라
동일 AI 모델을 쓰는 taptalk.xyz 본체 전 경로다.

---

## 1. 이 변경이면 리뷰 필수

다음 중 하나라도 diff에 포함되면 배포 전 리뷰가 필요하다.

- `src/lib/personas.ts` — 페르소나 정의 + systemPrompt
- `src/lib/debatePersonas.ts` — 토론 모드 페르소나 + systemPrompt
- `src/lib/safetyFilter.ts` — 위험 콘텐츠 필터 / 거절 응답 / 우회 프레이밍 차단
- `src/lib/crisisSafety.ts` — 자살·자해 위기 감지 및 안전 응답
- `src/lib/aiKillSwitch.ts` — 즉시 차단 스위치 (AI 생성 라우트 8곳에 배선)
- **`systemPrompt` 리터럴을 포함하는 모든 파일** (신규 추가 포함)
- **AI 모델명 문자열이 바뀌거나 새로 등장하는 모든 파일** (예: `gemini-3-flash-preview`,
  `gpt-4o`, `claude-*` 등 — 모델 버전 업그레이드도 포함)

CODEOWNERS가 이 경로들에 대해 `@ryanan86` 리뷰를 강제하고, CI 워크플로(`ai-safety-check.yml`)가
PR마다 자동으로 해당 여부를 알려준다. 다만 CODEOWNERS/CI는 보조 수단이다 — **최종 책임은
작성자가 아래 체크리스트를 실제로 확인하고, 배포 전 앱인토스에 통보하는 것**이다.

## 2. 리뷰어 체크리스트 — 앱인토스 AI 채팅·상담 정책 6항목

PR 리뷰 시 아래 6가지를 모두 확인한다. 하나라도 불충족이면 머지·배포하지 않는다.

- [ ] **위험 키워드·문맥 필터링** — 위험 요청이 키워드 매칭뿐 아니라 문맥(우회 프레이밍
      포함)까지 판단해 차단되는가. (`safetyFilter.ts` HARD_BLOCK + 2단계 분류기)
- [ ] **일관된 거절 응답** — 금지 요청에 매번 동일한 고정 문구로 거절하는가(LLM이 즉흥
      생성하지 않는가). (`safetyFilter.ts` REFUSAL_KO/REFUSAL_EN)
- [ ] **자살·자해 안전 프로토콜** — 위기 발화 감지 시 상담 연결 문구(109/1577-0199/1388)로
      즉시 전환하고, 세션을 자동으로 수업으로 되돌리지 않는가. (`crisisSafety.ts`)
- [ ] **사전 배포 검토** — 이 변경이 정말 배포 전 검토를 거쳤는가(이 프로세스 자체).
      리뷰 완료 없이 머지된 모델/프롬프트 변경이 프로덕션에 배포되지 않았는가.
- [ ] **즉시 차단 체계** — 문제가 발견됐을 때 코드 배포 없이 즉시 기능을 끌 수 있는
      수단이 있는가. (`aiKillSwitch.ts`, 4절 참고. **새 AI 라우트를 추가했다면
      그 라우트에도 `isAiDisabled()` 게이트를 넣었는지 반드시 확인한다** — 누락되면
      킬스위치를 켜도 그 경로로 모델이 계속 호출된다.)
- [ ] **우회 요청 차단** — "소설/영화 설정", "가정·이론", "실제로 안 쓴다"는 전제의
      요청이 프레이밍과 무관하게 차단되는가. (`safetyFilter.ts` BYPASS_FRAMING)

## 3. 앱인토스 사전 통보 의무

모델 또는 프롬프트를 변경한 배포는 **배포 전에** 앱인토스에 통보해야 한다.

- **어디서**: 앱인토스 콘솔의 채널톡(고객센터 채팅) 창구로 문의 접수.
- **언제**: 위 1절 트리거에 해당하는 변경을 프로덕션에 배포하기 **전**. 스테이징/프리뷰
  배포는 대상 아님, 실제 사용자에게 노출되는 배포만 해당.
- **무엇을**: 변경 요약(어떤 모델/프롬프트가 어떻게 바뀌었는지) + 2절 체크리스트 결과를
  간단히 첨부.
- **왜 급한가**: 위반 시 정책상 경고 → 노출 제한 → 노출 중단 순으로 제재된다(`crisisSafety.ts`
  코드 주석 참고). 사전 통보 없이 배포하면 이 절차 자체를 어기는 것이다.

## 4. 현재 구현 상태 (베이스라인)

리뷰어가 "이미 있는 것"과 "아직 없는 것"을 구분할 수 있도록 정리한다.

| 항목 | 상태 | 위치 |
|---|---|---|
| 위기(자살·자해) 감지 + 고정 안전 응답 | 구현됨 | `src/lib/crisisSafety.ts` |
| 위험 콘텐츠 필터 (키워드 1단계 + 문맥 2단계) | 구현됨 | `src/lib/safetyFilter.ts` |
| 일관된 거절 응답 (고정 문구, LLM 미생성) | 구현됨 | `src/lib/safetyFilter.ts` (`REFUSAL_KO`/`REFUSAL_EN`) |
| 우회 프레이밍 차단 (소설/가정/교육 목적 등) | 구현됨 | `src/lib/safetyFilter.ts` (`BYPASS_FRAMING`) |
| 페르소나 프롬프트 안전 조항 강제 주입 | 구현됨 | `src/lib/safetyFilter.ts` (`withSafetyClause`) |
| **즉시 차단 체계 (킬스위치)** | 구현됨 | `src/lib/aiKillSwitch.ts` (`isAiDisabled`). 배선: `chat`, `debate-chat`(POST/PUT), `ai-evaluate`, `speaking-evaluate`, `exam/grade`, `speech-coaching/analyze`, `study/plan`, `trending-topics`. 상태 확인은 `/admin/ai-status` |

위기 상담 연락처는 **109(자살예방상담전화, 2024-01 1393에서 통합)**, **1577-0199(정신건강상담전화)**,
**1388(청소년전화)**다. 24시간 무료이며 `crisisSafety.ts`의 고정 응답에 하드코딩되어 있다.

킬스위치는 `AI_KILL_SWITCH` 환경변수(Vercel 대시보드에서 값만 바꾸면 즉시 반영, "1"/"true"일 때만
차단, fail-open 설계)로 동작하며 고정 점검 문구를 반환한다. **현재 `chat/route.ts`에만 배선돼
있고 `debate-chat/route.ts` 등 다른 AI 라우트에는 아직 연결되지 않았다** — 이 문서를 갱신하는
시점 기준으로, 다른 라우트의 프롬프트/모델을 바꾸는 PR이라면 리뷰어가 킬스위치 배선 여부를
같이 확인해야 한다. 배선 전 라우트에서 심각한 문제가 발견되면 **즉시 롤백(이전 배포로 되돌리기)**이
사실상의 즉시 차단 수단이다.
